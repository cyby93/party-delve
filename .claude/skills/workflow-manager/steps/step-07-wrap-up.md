# Step 07 — Wrap Up

## Purpose

Open a PR, update `project-brief.md`, move the story to done, and surface the PR link to the user. One line of output.

---

## Instructions

### 1. Open Pull Request

Using `gh pr create`:
- **Title:** story `title` field from frontmatter
- **Base branch:** `main` (or current sprint branch if sprint tracking is active)
- **Head branch:** `feature/{story-id}`
- **Body:**

```
## Summary
{Phase Log summary — extract 2–3 key bullet points from Phase Log entries}

## Acceptance Criteria
{Full ## Acceptance Criteria section from the story body — rendered as a checklist with all items checked [x]}

## Agents Involved
{List of roles from pipeline with confidence scores}

🤖 Generated by the party-delve Cascade System
```

Store the returned PR URL as `pr_url`.

### 2. Update project-brief.md (Append-Only)

Read `project-brief.md`. Based on the pipeline roles used, append a summary entry to the relevant domain section(s):

| Pipeline roles used | Target section in project-brief.md |
|---|---|
| `simulation-engineer` | `## Simulation / Game Rules` (or closest matching section) |
| `host-engineer` | `## Host Client` (or closest matching section) |
| `mobile-engineer` | `## Mobile Controller` (or closest matching section) |
| `protocol-architect` | `## Contracts / Event Protocol` (or closest matching section) |
| `telemetry-agent` | `## Telemetry` (or closest matching section) |

**Append format** (at the bottom of each relevant section):
```markdown
### {story title} — {YYYY-MM-DD}
{2–3 sentences: what was built, what it enables, any key design decisions made}
```

Rules:
- Never overwrite existing content
- Append only — always at the bottom of the relevant section
- If a section doesn't exist in project-brief.md, add it as a new `##` heading
- Keep summaries concise: 2–3 sentences maximum

### 3. Move Story to Done

1. Read `_stories/active/{story-id}/story.md`
2. Update frontmatter: `status: done`
3. Write the updated file to `_stories/done/{story-id}.md`
4. Delete `_stories/active/{story-id}/` directory (including shards subdirectory)

### 4. Final Phase Log Entry

Append to `## Phase Log` in `_stories/done/{story-id}.md`:
```
### Workflow Manager — {datetime} [Complete]
PR: {pr_url}
Status: done
```

### 5. Surface to User

Output exactly one line:
```
PR ready: {pr_url}
```

Done. The cascade is complete.
