### D-016: Spirit-form phone state
**Decision:** Option A — modified controller. When a player enters spirit form:
- **Left zone:** Movement joystick remains — fully functional. Spirit-form players can still move.
- **Right zone:** 2×2 skill grid remains but 3 cells are locked (greyed, disabled). 1 cell is replaced by a class-specific **spirit-form ability** — different from the player's normal abilities, unique to spirit state.
- **Visual theme:** The entire controller UI shifts to a spirit-form visual theme. The Raw Earth base recedes; the Spirit Chant layer leads. The player's session color becomes the dominant accent. The atmosphere is luminous and ethereal — the player is in the spirit world. Locked cells are rendered very dim (high opacity mask). The spirit ability cell glows in the player's session color.
- **Exit:** Theme and grid return to normal if the player is revived before the run ends.

### D-015: Post-run summary — host screen
**Decision:** Single template, two emotional tones (victory vs failure). Not separate screen designs.
**Content shown:** Run outcome headline + flavour line, team Spirit Essence earned, player-by-player breakdown (name + class + times downed).
**Not shown on summary:** Run time, mastery milestones (those surface elsewhere).
**Return to Hub:** Triggered from the phone ("Return to Camp" button on controller) — not a host screen button. Host screen persists until players return.

### D-014: Spirit Bond assignment — host screen
**Decision:** Option B — ambient text overlay. When a bond is assigned:
1. Tether particle line appears in-canvas between the two bonded characters (colored, bond-specific)
2. Brief centered text fades in over the canvas: two player names + bond type (e.g. "Cyby · Dani — Fate Bond") — Uncial Antiqua, subtle spirit-blue glow, no panel or border
3. Text fades out after a few seconds; tether remains for the duration of the run
4. Bond-specific audio plays at assignment moment
Phone-side bond display:
- **Bonded players:** Full-screen takeover — controller disappears, bond card fills the screen. Player taps to dismiss / continue.
- **Non-bonded players:** Controller stays visible and inactive. A "Continue" button slides in from the top edge — same position, same style as the Interact button. Reuses the established slide-in pattern, no new UI concept needed.
- **Advancing:** Any one player (bonded or non-bonded) tapping "Continue" advances the whole group to the next level. Bonded players tap Continue on their bond card; non-bonded players tap the slide-in Continue button.

### D-013: Character selection UX
**Decision:** Class selection is phone-only. No class roster shown on host screen.
**Decision:** "Interact" button slides in from the top edge of the phone screen when the character is near a POI. Slides back up (off-screen) when the character moves away. Contextual — not a persistent UI element.
**Decision:** Class selection UI: horizontal scrollable card list. ~2–3 cards visible at once. Each card: class name (Uncial Antiqua) + role label + flavour line (Lora italic). Selected card has a highlighted state.
**Decision:** Ability briefing view appears automatically at the bottom when a card is selected (not a separate toggle). It contains the "Pick Selected Class" / finalize button — the bottom panel owns the confirmation action.
**Decision:** No "Select" button on individual cards. Tapping a card highlights it (spirit-blue border + bg shift). Selection state is communicated purely through card highlighting.
**Decision:** Button border-radius is reduced across all phone UI — less pill-shaped, more grounded/angular. Fits the Raw Earth base layer. Target: ~6–8px radius instead of full pill.
**Decision:** Interact button follows the same reduced-radius rule.
**Decision:** Host screen shows a small dialog/chat-bubble icon above the character's head while they are interacting with a POI.
Host shows no class roster. Class picking is entirely on the phone.

### D-009: Phone controller — cell content and cooldown
**Decision:** Resting skill cell shows: ability name (Lora italic) + input type badge (AUTO / RELEASE / TAP) only. No in-cell description or tooltip — a dedicated **ability briefing view** handles that before the player enters the controller screen.
**Decision:** Cooldown indicator fills the majority of the cell — large conic timer, not a small overlay. The cell has space; use it.
**Decision:** Ability icons/sprites replace the placeholder geometric shapes in a later production phase — UX structure is locked, asset pipeline is separate.

### D-008: Phone controller — landscape, 2×2 grid, floating joystick cells
**Decision:** Phone is held in landscape orientation.
- **Left zone (~40% of screen):** Movement joystick — floating, spawns at touch position
- **Right zone (~60% of screen):** 2×2 grid of 4 rectangular skill cells
- **Each skill cell:** Displays as a rectangle with skill icon + name + cooldown overlay. When touched, a virtual joystick ring spawns at the exact touch position within the cell. Player drags within the cell for directional aim (Joystick-AutoFire / Joystick-Release types). For Tap-type skills the cell acts as a pure tap button — no joystick spawns.
- **Grid structure is fixed across all classes.** Only the skill content (which ability occupies each cell) is class-specific. The GDD note about "class-specific layout" is incorrect and overridden here.

**GDD correction:** GDD §Controls states "4 ability slots — class-specific layout, not standardized across classes." This is wrong. All classes use the fixed 2×2 grid. Only cell contents differ per class.

### D-004: Visual direction — two-layer system
**Decision:** Combine Raw Earth + Spirit Chant as two distinct design layers.
- **Raw Earth layer** (base): backgrounds, surfaces, forms, body text, structural chrome, stable UI skeleton
- **Spirit Chant layer** (accent): active selections, highlights, VFX moments, spirit bond tethers, corruption glows, purification pulse, spirit forms
The world feels grounded and earthy by default; spirit energy surfaces only where it is earned (selections, bonds, damage, purification).
