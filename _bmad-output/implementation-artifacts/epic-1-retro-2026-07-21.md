# Epic 1 Retrospective: Foundation Platform

**Date:** 2026-07-21
**Participants:** Cyby (Project Lead), Developer, Product Owner, Senior Dev, QA Engineer
**Status:** First retrospective run on this project (no prior retro to compare against)

## Context

This retro was run retroactively — Epics 1 through 6 are already complete (`done` in sprint-status.yaml) by the time it happened, and no retro had been run on any of them. Epic 1's own content is pure infrastructure (session lifecycle, tick loop, join flow) with no UI surface, so there was no fresh memory to draw on; this retro is based entirely on the story records and code-review history (10 stories: 1.1–1.10, of which 1.7–1.10 were post-hoc hardening passes).

## Epic 1 Summary

- Completed: 10/10 stories (100%)
- 4 of the 10 stories (1.7, 1.8, 1.9, 1.10) were hardening passes closing deferred findings, not new scope
- Deferred-work.md ledger discipline held throughout — nothing was silently dropped

## What Went Well

- **`host-session.ts` / `mobile-session.ts` module pattern** (established in 1.3) was cleanly reused and extended through 1.4–1.6.
- **Contract-test discipline**: every `net-protocol` change got a round-trip test; coverage grew from 0 to 15+ tests across the epic without regressing.
- **Deferred-work.md + hardening-story cadence**: real findings got tracked and eventually closed rather than forgotten, even when they took multiple stories to fully resolve.

## What Was Challenging

1. **Recurring Colyseus API surprises** — `room.id` vs `room.roomId`, `onLeave(client, code?)` signature, `allowReconnection` semantics, `client.reconnect(token)` — each got documented as a "learnings" note in the story that hit it, but the pattern of rediscovering the same class of API surprise repeated across stories 1.2–1.6.
2. **Stale-closure bugs in React session code** hit three separate stories (1.3, 1.5, 1.7) before a consistent ref+state dual-pattern was adopted.
3. **Design-token discipline gaps** (raw CSS px/rgba instead of `var(--*)`) were flagged in three consecutive stories (1.3, 1.4, 1.5) — same finding, repeated.
4. **`App.tsx` reconnect/URL logic** took four separate hardening passes (1.7 → 1.8 → 1.9 → 1.10). Each patch was correct and in-scope for its story, but the file arguably needed one structural pass instead of four sequential patches — nobody stepped back to make that call mid-sequence.

## Action Items

1. **Add server-side authorization check for the `isHost` flag.**
   Owner: Simulation Engineer (session lifecycle, `apps/simulation-server`)
   Why now: flagged as a real security gap since Story 1.3; relevant again given Epic 7 (Progression & Persistent Meta) will introduce registered accounts — this debt should not carry into an auth-bearing epic unaddressed.

2. **Add automated test coverage for `apps/mobile-controller`.**
   Owner: Mobile Controller Engineer, with QA + Telemetry Engineer support (`tests/**`)
   Why now: zero coverage on a surface that every subsequent epic (2–6) has continued to build on top of, compounding the gap.

Not escalated this retro (left as tracked, deferred): Zod validation on `deserialize()`, E2E reconnect test stub. Both remain in deferred-work.md at their existing priority.
